# 收藏管理、列表快捷收藏与画廊布局修复

## 用户反馈

- 浏览页右侧有大块黑色空白。
- 收藏夹显示不完整，不能在软件内部管理。
- 必须进入图片详情才能收藏。

## 本次修改

### 画廊布局

隐藏侧栏参与隐式布局计算，挤占浏览画廊空间。改为明确的侧栏/画廊坐标和尺寸：普通浏览不留侧栏位置；收藏模式侧栏宽 270px，其余全部给画廊。

最初的组件回归在 1200px 窗口下测得浏览视口只有 674px。修复后宽度断言通过。真实 Release 检查又发现收藏模式中间容器没有明确起点，侧栏居中偏移；新增断言实际失败为 `collection sidebar was centered instead of left-aligned: 465`，随后为容器和侧栏设置明确位置/尺寸，复测通过。

### 收藏夹完整性

- 识别条目本身就是 `<a class="collection">` 的结构，不再仅搜索其子链接。
- 跟随同源、同账号的 next-page 链接，按 ID 合并分页；循环或超过 100 页时明确报错，不把部分列表声称为完整列表。
- 保留 Unicode 长名称，侧栏换行显示。
- 识别公开、私有标志；没有证据的可见性保持未知，不擅自视为公开。
- 完整私有列表需要已确认的网页登录会话，公开账号列表不代表自己的全部收藏。

### 列表直接收藏

每张卡片右上角独立爱心点击区，打开快捷收藏窗口，不进入详情。读取状态后选择目标收藏夹并确认，也可取消收藏。成功核对后更新已知爱心状态；未知状态不冒充已核对结果。

快捷窗口和管理窗口独立于主窗口，且带账号/请求代次检查。会话过期或账号变化后旧状态不能用于提交；未登录时不提交收藏。

### 软件内管理

“我的收藏 → 管理收藏夹”打开应用自己的独立窗口，包含新建、重命名/公开性修改、刷新，以及需要显式勾选确认的删除。

管理请求只使用从新鲜网站 HTML 中发现的同源管理链接/表单，保留 CSRF 和方法覆盖字段，不猜写入端点，不 GET 删除链接。新建不能选择现有收藏夹编辑表单。未知可见性修改需本人确认，重复名称创建会被阻止。

写入结果通过重新读取列表核对，网络结果不明不自动重发。页面结构不支持时明确报错，可选择“内置网页管理”，在同一应用 WebView2 会话继续，而非打开系统外部浏览器。

## 未验收边界

没有自动修改用户真实收藏或创建/删除真实收藏夹。真实账号仍需本人完成网站人机验证/登录；未对照其全部私有收藏夹，也未完成真实网站 CRUD/收藏写入验收。

管理表单兼容逻辑已通过本地模拟，但尚未用实际已登录账号的管理 DOM 验证，不能据此承诺网站所有管理表单均兼容。遇到未识别结构会停止原生提交并提示使用内置网页管理，而不会猜测写请求。

这批修复不表示 Windows 所有功能、Android、持久数据库、下载队列和打包升级已完成。没有读取/输出真实 Key、密码、Cookie 或 CSRF，也没有覆盖用户配置。

## 后续修正：紧凑爱心和竖图上下留黑

用户提供的 3978×7087 竖图对应公开壁纸 `6lw16w`。实际下载三种 CDN 缩略图核对：`large` 为 432×243（横向裁切），`small` 为 300×200（裁切），`original` 为 169×300（保留原始比例）。此前按原图竖向比例生成卡片，却把横向裁切预览 contain 到其中，导致大块上下留黑，且人物内容已在 CDN 预览中被截掉。

- 普通/API 列表优先使用 `thumbs.original`，缺失/空白才回退其他尺寸。
- 网页收藏 HTML 的标准 small/lg 路径转换为同一壁纸的 original 缩略图路径；仅允许匹配当前 ID 的固定 CDN 路径。
- 不改成 cover 裁切、不拉伸原图；自适应布局继续按原图宽高比例分配卡片。
- 爱心按钮从 36×32px 缩为 24×24px，图标从 23px 缩为 16px；默认去掉明显边框，仅悬停/已收藏时强调。
- 两条取图路径的新增回归均先失败，修正后通过；同时检查自适应卡片比例和缩小后爱心/图片点击区独立。
- 本轮 `cargo test --workspace`：核心 38 通过、桌面 72 通过，各有 1 个未在全量中运行的忽略项；严格 Clippy、格式检查和 Release 构建通过。未修改认证/网站写入逻辑，本轮未重复原生登录测试。

仍保留明确的“等尺寸网格”设置：该模式的固定卡片可能存在比例留白；默认自适应模式应匹配原图比例。缩略图整数取整可能造成不到约 1px 的细微误差，不应再出现截图中的大块黑区。
