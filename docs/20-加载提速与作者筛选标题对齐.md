# 原图加载提速、作者筛选与标题栏对齐

## 本轮修复

### 1. 原图加载

保留完整原图分辨率，不恢复 2000px 降采样，也不加回原图大小/解码内存配额。

旧流程先等待 `/w/{id}` 详情 API，再下载原图；即使列表已有原图地址也串行等待。每次重开同一张图都重新传输、解码，UI 线程还会先清零一张完整 RGBA 缓冲再复制。

现在：

- 新增 `detail_loading.rs`，列表已有地址时原图与元数据并行；缺失地址时才从详情响应补取。请求仍携带详情代数，旧结果不能填入新的详情。
- `ImageLoader` 复用最近一张已解码原图，重复打开不重新网络传输/解码；只保留最近一张，不累计整个原图库，不持久化原图文件。
- 查询/权限失效会清除此缓存；失效前发出的工作不会重新写回新一代缓存。
- 后台准备共享像素缓冲，UI 线程只创建 `slint::Image`，不再做大块清零和像素复制；缓存命中共享像素，不深拷贝。
- 详情初始明确显示“正在加载原图…”，完成后显示真实原图尺寸。原图可先于作者/标签等元数据完成。

不承诺网络或完整解码成本消失；首次加载仍可能需要数秒。

### 2. 作者主页分级

之前仅 SFW 确实由应用写死：API 查询、返回过滤与预览入口都限制为 SFW。本轮移除此硬编码：

- 打开作者主页时继承主界面当前 SFW / Sketchy / NSFW 选择。
- 作者页上传作品和公开收藏内容新增独立复选框；切换筛选重载第一页，不改变主窗口筛选、列表或滚动。
- 全不选时回退 SFW，不发送 `purity=000`。
- NSFW 必须同时满足当前设置允许、有 Key、用户选中。不会自动打开权限或保存设置。
- 资料 HTML 与收藏摘要始终无 Key；只有明确选择且获准的 NSFW 内容请求才使用当前 Key。每次从当前主状态选择客户端/凭据，不捕获过期 Key。
- Key/权限变更时丢弃旧请求，清除旧作品/预览/图片缓存与收藏选择；UI 同步当前可用分级，重新读取当前筛选内容。
- 默认仍是 SFW，并不等于作者页只能 SFW。非 SFW 的总数也不能用此前 SFW 数量推断。

### 3. 标题栏

旧 `HorizontalLayout` 使 20px 图标靠上，而文字占满 40px 标题栏；回归实测图标中心 y=10，文字中心 y=20。

所有复用 `StudioTitleBar` 的原生窗口改用明确定位：图标 x=16、y=(40−20)/2；文字 x=46、占满 40px 并垂直居中。保留标题栏40px、按钮138px和原生命中区域，不改窗口拖动/缩放实现。

本轮仅修复该局部对齐，不把整套界面宣称为10/10或完整跨DPI/辅助功能审计通过。

- 原图被人为阻塞的详情接口挡住，等待超过1秒；修复后详情接口尚未释放时即可收到完整原图事件。

## 保留边界

首次原图加载仍受源站速度、原始像素数量和渲染能力影响；不以降低画质绕过。最近原图缓存仅保留一张，换查询、权限失效或换图后不保证旧图仍命中。快速连续点不同原图的更深层取消/网络队列优化不在本轮宣称完成。

NSFW的真实服务器Key有效性/内容访问本轮未验收，仅验证权限与Key选择、结果过滤的隔离分支。网站安全验证、站内写入、跨显示器DPI等既有边界不因本轮通过而取消。仓库无Git，未提交。
