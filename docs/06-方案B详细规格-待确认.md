## 一、Slint 能力边界（已实测，直接决定 UI 能做成什么样）

### 1.1 Slint 官方自带的控件只有这些

实测 `internal/compiler/widgets/material/` 目录，**全部**可用的 Material 3 控件：

| 有 ✅ | 无 ❌ |
|---|---|
| Button / CheckBox / Switch / RadioGroup / Slider / SpinBox | **卡片 Card** |
| ComboBox / LineEdit / TextEdit | **Tab 栏（有 TabWidget 但样式基础）** |
| ProgressIndicator / Spinner / DatePicker / TimePicker | **下拉刷新** |
| Menu / GroupBox / TabWidget | **Toast/Snackbar** |
| ScrollView / ListView / StandardTableView | **图片网格 Grid** |
| SystemTrayIcon / Dialog / PopupWindow / Tooltip | **抽屉 Drawer** |
| | **下拉选择多选** |
| | **Chip 标签** |

**结论**：搜索面板的所有控件（单选/多选/滑块/下拉）**基本够用**，但**卡片、标签 Chip、Toast 需要自己写**。

### 1.2 ★ 虚拟滚动：能做，但必须自己实现

`ListView` 内部有这句：
```slint
private property <length> item-height: self.content-height / self.model.length;
```

**这意味着 `ListView` 只支持等高等宽的单列列表**，不能直接做瀑布流/网格。

**好消息**：`ScrollView` 暴露了虚拟滚动所需的一切：
```slint
out property <length> content-y;      // 当前滚动位置
out property <length> visible-height; // 可视区高度
callback scrolled();                  // 滚动事件
```

**所以方案是**：自己用 `ScrollView` + 计算可视范围 + 只加载可见行的图片。这是可行的，但需要写代码（约 2–3 天）。

### 1.3 没有内置的图片异步加载 / 缓存

`Image` 元素只有 `source`（image 类型）、`image-fit`、`image-rendering`、`colorize` 等。**没有 URL 加载、没有缓存策略**。

已在原型中验证的做法（可复用）：
- `reqwest` 下载 → `image` 解码 → `resize_exact` 降采样 → `Image::from_rgba8`
- 内存缓存需自己用 `lru` crate 实现

**⚠️ 一个必须你拍板的设计问题**：

## 三、粒度对齐：Android 端（Kotlin + CMP）

### 3.1 与桌面端的关系

**共享什么、不共享什么**——这是方案 B 最需要对齐的点：

| 层 | 共享方式 | 说明 |
|---|---|---|
| 数据模型 | **Rust core 定义，uniffi 生成 Kotlin 类型** | 两端字段完全一致 |
| API 调用 | **Rust core 实现**，Kotlin 通过 uniffi 调 | 限流器也只有一份 |
| 清洗规则 | **Rust core 实现** | 两端行为一致 |
| 本地数据库 | **Rust core（SQLite via rusqlite）** | 两端共用一个 schema |
| 图片加载 | **各端自己实现** | 桌面用自建 LRU，安卓用 Coil |
| UI | **完全各自实现** | Slint vs Compose |

### 3.2 ★ 这里有个必须先说清的架构决策

**SQLite 到底放在 Rust 还是各端？**

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. Rust 里用 rusqlite** | 逻辑统一、schema 单一真相 | Android 上 rusqlite 需编译 SQLite，体积 +2MB；且 uniffi 要把查询结果转成 Kotlin 对象 |
| **B. 各端用原生 DB**（桌面 rusqlite / 安卓 Room） | 各端性能最优、生态原生 | **查询逻辑要写两遍**，schema 容易漂移 |

我倾向 **A**（统一在 Rust），代价是多 2MB，但避免了最麻烦的"两份逻辑不一致"问题。

**你怎么选？** → ☐ A 统一在 Rust / ☐ B 各端原生

### 3.3 Android 端页面与桌面保持一致的清单

| 页面 | 与桌面差异 |
|---|---|
| 搜索 | 筛选面板改为**底部抽屉**（桌面是左侧栏） |
| 网格 | 2 列（竖屏）/ 3–4 列（横屏） |

| 自动轮换 | 新增：WorkManager 定时换壁纸（桌面无此功能） |

## 四、UI 视觉风格（需要你定调）

Slint 只有 Material 3 和 Fluent 两套内置主题。

| 选项 | 风格 | 工作量 |
|---|---|---|
| **A. Material 3 深色** | 标准 Material，圆角卡片 | 低（用内置） |
| **B. Fluent 深色** | Windows 11 原生风格 | 低（用内置） |
| **C. 自定义（仿 wallhaven 网页）** | 深色 + 青绿点缀（`#66cccc` 是 wallhaven 主色） | 中（需自己写样式） |

**我推荐 C**：用 wallhaven 的品牌色（实测 API 里返回的主色就常含 `#66cccc`），让桌面端看起来像"wallhaven 官方桌面版"。

**你选：** ☐ A / ☐ B / ☐ C / ☐ D
