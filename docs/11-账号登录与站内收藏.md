# 账号登录与站内收藏：实现与验收边界

> 后续修复已改用 WebView2 同会话网页登录，本文中的 reqwest 密码登录和外部浏览器限制是历史实现。最新行为和真实验证结果见 [12-网页登录验证会话修复.md](12-网页登录验证会话修复.md)。

## 更正

官方 API 没有写接口，不等于客户端只能读收藏。本轮已检查 Wallhaven 网站公开 HTML 和前端脚本，加入独立于 API Key 的网站登录会话及原生收藏 POST 流程；不能再把 API 限制当作整个客户端的能力上限。

## 网站请求依据

- 当前网站脚本 `wh-core-4ddcb6667c1fa980f336.min.js` 的收藏逻辑：`#fav-button` 为 `add-button` 时点击 `a.add-fav`，否则点击移除按钮本身；`$.post(this.href)` 后读取 JSON `status` 和替换按钮的 `view`。
- CSRF 来自页面 `meta[name=csrf-token]`；收藏动作地址从新获取的已登录页面读取，不硬猜路径。
- 登录表单从 `/login` 返回 HTML 动态解析 action、用户名/邮箱字段、密码字段和隐藏 `_token`。
- 收藏页结构来自公开样本 `/user/Bishoujo/favorites`、`/user/Bishoujo/favorites/1885433`：收藏夹链接/名称/数量、壁纸 ID/分辨率、`data-pagination`。

## 实现

### 网站会话

- 独立设置窗口新增网站用户名、密码和登录/退出入口。
- `website.rs` 用 reqwest Cookie jar，Cookie 仅保留于当前应用内存；密码不写配置、日志，提交时立即清空界面密码框。
- 密码与 API Key 完全分开。网站登录不要求 API Key；退出网站会话不会修改 API Key。
- 仅接受 `https://wallhaven.cc` 同源 action 和重定向；限制超时、响应体大小，错误不包含原始页面、密码、Cookie 或 CSRF。
- Cloudflare、CAPTCHA、二步验证显示需本人处理，不自动绕过。普通页面的 Cloudflare precursor 脚本不等于质询。
- 登录成功必须从已登录用户面板观察到用户名和退出证据，不能只以 HTTP 200 判定成功。
- 网站会话不持久化；关闭应用后需重新登录。当前浏览器备用入口不会自动把外部浏览器 Cookie 导入应用，不会假称已共享会话。

### 收藏操作

- 详情新增读取站内收藏状态、收藏夹目标选择、收藏、取消收藏和刷新状态。
- 每次写入前重新获取页面状态和动作地址，发送网站原生 POST（CSRF、XMLHttpRequest、JSON Accept）。
- 禁止写请求自动重试；已在期望状态时不发送 POST。
- 同源 307/308 重定向也禁止自动跟随，避免重发 POST；检测到会话未认证时丢弃过期会话并清空网站私有收藏视图。
- 只有网站返回成功且重新读取到目标状态才提示已核对成功；网络中断、结构变化或核对失败显示结果未确认。
- 请求版本号拒绝切换详情/退出会话后的旧结果，禁止双击并发写入。
- 网站会话可读取自己收藏夹和分页内容，无需再填 API Key；内容仍受客户端纯度开关限制。
- API Key 保留为另一个可选通道，支持验证凭据、读取自己/公开收藏夹和内容；不能用于网站写入。
