# Windows 桌面端修复与验收记录

> 本文替代此前的“桌面端功能完成，可日常使用”结论。此前把编译、单元测试和截图等同于完整可用性验收，不准确；以下仅记录已执行的检查和仍未完成的范围。

## 一、本次三项问题

### 1. 输入 API Key 后出现 `invalid type: string "24", expected u32`

原因：客户端反序列化数字字段时只接受 JSON 整数，而认证响应可能用字符串表示数字，例如分页字段 `per_page: "24"`。这是响应模型兼容性缺陷，不能由这条 schema 错误推断用户 Key 无效。

修复：`rust/core/src/models.rs` 的数字字段统一接受整数或可解析的十进制字符串；缺失/null 保留为 None，非法值与溢出仍返回错误，不静默伪造数值。

回归覆盖：字符串/整数混合响应、缺失/null、非法/越界值。`authenticated_response_accepts_string_numbers` 明确覆盖 `per_page: "24"`。

### 2. 设置在原窗口内打开，并导致主窗口缩小

原因：旧实现将设置当成主窗口内部页面，设置页的布局约束会影响同一个 Window；返回浏览页不是切回独立窗口。

修复：独立实例化 `SettingsWindow`，标题为 `WallHaven Studio — 设置`，使用自己的显示/隐藏、尺寸和草稿状态。打开和关闭设置不切换主窗口页面、不修改主窗口尺寸。Key 输入框为密码模式，留空保留现有 Key。

### 3. 必须到底部才开始加载下一页

原因：旧请求触发过晚；仅把网络请求放后台线程，并不等于提前加载。

修复：
- 第一页收到后主动请求第二页，无需滚动。
- 滚动时，当剩余内容进入约 1.5 个视口的提前量，即 `offset + viewport * 2.5 >= content_height`，后台请求后续页。
- 收到分页结果后再次判断是否需要补充内容。
- 同一查询只保留一个在途分页请求；搜索代次丢弃过期结果。
- 随机排序沿用接口返回的 seed，避免翻页随机重排。
- 空页或全重复页停止连续预取，避免无新增内容时空转。
- 网络与图片解码在工作线程完成，Slint 图片与 UI 状态只在 UI 线程操作。

## 二、附带修复的直接相关边界

- 新搜索、认证变更或关闭 NSFW 触发重查时，作废旧详情/预览请求，清除旧详情图片并返回浏览，防止旧结果重新显示。
- 修复令牌桶轮询会取消 429 冷却时间的问题；提前预取仍受 API 限流约束。
- 配置保存失败不会退回明文 Key；Windows DPAPI 加密失败会报错。配置测试均使用隔离路径。

## 六、尚未完成或尚未验收

- 原图下载已有流式写入与进度代码，但本轮未完成“GUI 点击下载 → 校验最终文件”的端到端验收。
- 设置保存持久化已有隔离测试，但本轮未在真实用户配置上反复保存/更换 Key 做破坏性验证。
- 全部筛选条件、长时间快速滚动、异常网络/限流场景未做完整 GUI 验收；缩略图队列仍有进一步限界空间。
- 统一 SQLite/本地数据清洗、设为壁纸/自动轮换、安装包、Android 与 UniFFI 集成仍未完成。
- 不应再把单个查询结果推断成“全站固定 254 页上限”；分页以实际响应为准，并防御空页/重复页。
- 官方 API v1 为只读；不能据此承诺网站的收藏写入、上传、论坛等写操作。

结论：本记录确认三项用户报告缺陷的针对性修复及上述检查，不代表整个 Windows 客户端或全站功能已完成，也不自动转入 Android 开发。
