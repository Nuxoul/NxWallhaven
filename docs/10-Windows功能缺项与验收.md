## 实际发现并修复的回退

首次 GUI 测试发现展开高级筛选导致主窗口宽度从 1280 缩为 860；仅 headless 测试不能捕获这个原生后端问题。已保持筛选区实例、显式声明窗口可调整的最大尺寸并设置初始逻辑尺寸。最终 Release 实测：启动、展开、搜索后均为 1280×820 内容尺寸（含标题栏截图 1280×850），并新增尺寸保持断言。

## 检查与测试边界

- `cargo test --workspace`：核心库 28 passed、1 ignored（联网测试）；桌面端 32 passed。
- `cargo fmt --all -- --check`、严格 `cargo clippy --workspace --all-targets -- -D warnings`、Release 构建通过。
- 新筛选测试先失败，补映射后通过；覆盖控件到 API 参数、无效宽高/颜色、默认条件、Toplist 范围与无效输入保留结果。
- 新下载测试使用本地 HTTP 服务，覆盖完整字节/进度、断流、404、已有文件不覆盖。
- 原生平台测试验证参数、文件大小/解码限制、Unicode 路径、BMP 原子替换，不修改真实剪贴板/壁纸，不启动文件管理器。
- GUI 点击复制链接的结果另行核对；读取只输出与预期公开链接是否相等，不展示其他剪贴板内容。
- 测试启动器被 computer-use 拦截，命令行隔离实例未持续存活，未将其视为配置保存验收成功。后续正常启动真实程序，仅做不改配置的操作；真实配置大小与修改时间均未变化，未读取或输出 API Key。
- GUI 下载原图保留在用户默认下载目录，没有自动删除。
- 当前目录不是 Git 仓库，无法提交或基于提交差异审查；以当前文件与检查结果记录。
- 一次针对本轮新增文件与控制器接线的只读正确性审查完成，未发现阻塞；审查不代替 GUI 验收。
