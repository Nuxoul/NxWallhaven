# 窗口缩放：固定分行、铺满视口与闪烁修复

## 用户要求

Android 方案已同意，但实施前先修复 Windows：最大化后画廊没有铺满、顶部闪烁；窗口变大时保持原来每行的图片成员和数量，只缩放单元格及图片，不能把原来一行 5 张重新排成 9～10 张。本轮没有修改 Android 代码。

## 复现与原因

先加实际桌面布局/渲染入口回归，再修改实现：

```powershell
cd D:\Code\wallhaven\rust
cargo test -p wh-desktop resize_regression -- --nocapture
```

初次运行 2 项失败：

- 原比例布局在 1264 宽时每行 5 张，宽度改为 2544 后变成 9 张，行内成员改变。
- 同一批已加载图片重复 `render` 时，整个 `ModelRc` 被替换，而不是更新原有卡片。

原有逻辑按实际宽度重新分行，统一网格也按宽度重新计算列数；缩放并不等于放大原有画布。`visible-width`/滚动变化回调中同步修改状态、重排及替换模型，状态借用冲突时直接跳过，最终宽度可能遗漏；视口高度也只在部分事件更新。每批缩略图完成再次替换整批模型，会造成控件重建和画面不稳定。

## 修复

新增 `rust/desktop/src/gallery_layout.rs`：

1. 主画廊按默认 1280 窗口的可用画布宽度 1264 分行；作者页按默认 960 窗口的可用画布宽度 912 分行。根据实际视口比例缩放 x/y/w/h 和间距。
2. 普通窗口、最大化、窄窗口和还原使用同一行成员。原比例模式每行数量随图片比例而不同，但不因窗口尺寸变化而改变。统一网格也不随窗口变宽增加列数。没有把所有行强制成 5 张。
3. 原图比例不变；完整行铺到可用区域右边缘。末行不足时仍不强行放大，沿用既有末行规则。
4. 共用原地模型同步：保留 `VecModel`，只更新改变的卡片，滚动时增删必要边缘，不为每次缩略图完成销毁整个画廊。
5. 当前可见卡片已持有的图片在 LRU 淘汰后仍保留，不闪回加载占位；离开可见/预加载区域后仍可释放，不是永久保留所有图片。

`main.rs` / `ui/app.slint`：

- 宽度、高度、滚动偏移、滚动范围直接绑定实际 ScrollView 值。
- 移除在布局变化回调中重排/渲染；现有 40ms 事件泵统一读取最终尺寸并更新，不丢最后一个宽度事件。
- 高度单独变化也刷新可见区域；尺寸不变不反复重排。
- 缩放时按比例保留滚动位置，约束在内容范围内，不突然跳回顶部。
- 外层内容矩形明确裁剪，防止内容绘制越过正文区域。
- 原有分页/预取和请求代数保留，缩放本身不发起搜索重载。

作者作品及公开收藏列表使用同一缩放和模型同步实现，保留独立窗口/筛选及自动连续加载。不改下载、原图缓存、账号和网页登录逻辑。

## 自动化验证

新增 `resize_regression.rs` 4 项常规测试：

- 两种布局在 1264→2544→900→1904→1264 宽度间切换，每行成员不变、单元格同比缩放、比例/右边缘正确。
- 重复渲染保留原模型及已加载图片，主动清空 LRU 后当前显示不变成占位图。
- 实际 Slint 窗口从 1280×820 改到 2560×1440，读取实际视口宽度 >2500、高度 >1000；滚动偏移同比保留、还原恢复，稳定尺寸不振荡。
- 原地同步正确处理滚动重叠、头部插入、末尾追加、空列表和重新显示。

使用全新隔离 `WH_STUDIO_CONFIG_DIR` 启动本次发行 EXE，不加载真实用户配置/Key/浏览器资料；读取公开 SFW 列表。只操作本次创建的进程，没有向真实下载目录写文件、设置壁纸或执行账号写入。

- 实际正常窗口：**1280×820**。
- 调用当前 UIA“最大化”按钮，`IsZoomed=true`；Windows 外框测得 **2576×1416**（包含屏幕外的原生边框，不是可用画布宽度）。
- 正常首行 **6 张**，最大化后仍为相同顺序的 **6 张**：3840×2160、1500×2000、1500×2000、1500×2000、2560×1600、2880×1800。
- 第一张标签宽 292→597，最后一张标签宽 262→536，卡片随视口放大；最后一张标签右边缘约 x=2553，未保留此前窄画布的右侧空区。
- 最大化后从窗口最顶端 y=0 起的标题栏/导航区域连续 **20 次**像素采样，**1 个唯一 SHA-256**，该采样期间未观察到顶部闪烁。最终截图分别有 217299/541587 个不同 RGB 颜色，不是空白帧误判。
- 点击“还原窗口”恢复 **1280×820**，首行标签的顺序及坐标/宽度均恢复。
- 验收进程正常关闭，没有遗留进程；不会把失败的前几次脚本名称匹配尝试计为通过（PowerShell UTF-8 解码问题已纠正）。

证据保存在会话 scratch 的 `resize-native-normal.png`、`resize-native-maximized.png`、`resize-native-acceptance.json` 和 `resize-final-tests.log`，不将机器相关截图/日志提交源码仓库。
