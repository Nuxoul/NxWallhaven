## 三、实现要点（供 Android 端复用）

### 3.1 justified 布局算法

核心思想：
1. 依次把图加入当前行
2. 当「按目标行高排列后总宽 ≥ 容器宽」时结算该行
3. 结算时反解行高 = `(容器宽 - 间距总和) / 宽高比之和`，使总宽恰好等于容器宽
4. **末行不满时不拉伸**，保持目标行高（避免最后一行图片被放大到失真）

宽度变化时只需重算 O(n)，无需重新请求网络。

### 3.2 多线程并发加载

- 8 个工作线程共享 mpsc 队列
- 每个任务自带回调（避免全局可变状态竞争）
- 解码后按目标尺寸（640×640 上限）降采样，防大图吃内存
- generation 号作废旧任务（用户改搜索条件时）

**关键 bug（已修）**：`loader.invalidate()` 返回的是 loader 自己的 generation，必须用它的返回值传给 `load_batch`，不能用 `AppState` 的 generation——两者数值不同步，会导致所有图片任务被判定过期而静默丢弃。**症状是界面只显示占位符，不报错。**

### 3.3 Slint 关键限制（已踩完）

| 限制 | 应对 |
|---|---|
| `slint::Image` 非 `Send` | 后台只传 `(w, h, Vec<u8>)`，Image 在 UI 线程 `upgrade_in_event_loop` 内构造 |
| `GridLayout` 动态索引 panic | 不用 GridLayout，改为绝对坐标定位（`x`/`y` 属性） |
| `ListView` 只支持等高行 | 同上，自己实现布局 |
| 不支持 `%` | 用 `Math.mod()` |
| `if` 内不能含多个元素 | 用 `opacity` 控制显隐 |
| `export component` 非 Window 会报错 | 内部组件去掉 `export` |
| `width` + `min-width` 冲突 | 用 `preferred-width` |
| `viewport-y` 已废弃 | 用 `content-y` |
| `LineEdit` 无 `vertical-alignment` | 移除该属性 |
