# 多窗口 UX 与原图阶段加载

> 后续更新：[磁盘图片缓存与单文件发行](22-磁盘图片缓存与单文件发行.md) 已替代本文“不持久化原图”的历史状态。当前原图文件缓存到本地，加载后保存直接复用，重启后仍可使用；页面失效与磁盘清理已分离。本文下方测试计数和桌面记录保留为当时结果。

## 用户要求与实现

本轮保持 Rust + Slint / Windows，不改架构，不降低原图分辨率，也不把图片详情退化成只显示缩略图。

### 图片详情与作者主页支持多开

新增 `ui/detail.slint` 与 `src/window_hub.rs`：

- 主画廊点击图片不再切换主窗口页面，而是创建独立、非模态 `DetailWindow`。
- 作者主页的上传作品和公开收藏图片也调用同一个详情窗口创建入口，不再用作者页内嵌预览覆盖原列表。
- 可同时存在多个图片详情，包括同一图片的多个窗口；每个窗口有自己的图片、缩放、元数据、加载/下载状态、请求代数和结果队列。
- 点击详情中的作者可创建新的原生作者主页，多个作者页可以并存。来源详情、作者页和主画廊各自保留状态。
- 关闭一个详情只释放该实例，不关闭其他详情/作者页。关闭主窗口统一隐藏并释放这些子窗口和辅助工具，保持原网站会话正常 shutdown。
- 保留缩放/平移、下载原图、复制链接、系统浏览器打开、打开目录、设置壁纸、标签/颜色搜索和作者入口。站内收藏通过现有快捷收藏工具接收该详情的真实壁纸 ID，不依赖主窗口唯一“当前详情”。标签/颜色搜索明确在主窗口执行，不悄悄替换当前子窗口内容。
- 受限详情在 Key/NSFW 权限变化时关闭、丢弃旧事件；普通 SFW 详情不受无关权限变化中断。打开受限详情仍要求当前允许且有 Key，不自动开启内容权限。

设置、快捷收藏、收藏管理属于操作工具，继续复用各自实例而不是任意堆叠。图片详情与作者主页不再是全局单例。

### 弹窗居中

`window_chrome.rs` 新增统一定位：以来源应用窗口的原生位置和物理尺寸计算中心，并限制在所属显示器工作区，避免标题栏跑出可见范围。先设置详情/作者页初始尺寸，再定位，解决 Slint 首次布局从最小尺寸扩展后偏移的问题。

- 设置和收藏管理相对主窗口居中。
- 从详情打开作者、从作者打开详情，均相对触发它的来源窗口居中。
- 快捷收藏从详情打开时相对该详情居中。
- 只在打开时定位，不在后台加载/刷新时持续把用户拖动过的窗口拉回中心。
- WebView2 登录窗口仍保留系统标题栏、原会话与安全验证逻辑，仅在显式显示/导航时相对当前应用窗口或主窗口定位；其实际桌面坐标本轮未测，不能算作已实测居中。

### 加载反馈与优化

新增 `OriginalProgress` / `preview_observed`：连接、传输字节/总量、解码、完成阶段。详情显示已知总量时的进度条，失败有“重试加载”，完成后给出原图实际尺寸及网络/解码耗时。

同一原图 URL 同时被多个详情请求时：

- 共用一次正在进行的 HTTP 请求和完整解码，结果共享像素缓冲；不是每个窗口重复下载/解码。
- 不同 URL 不被一个网络大锁串行阻塞。
- 成功仍只保留最近一张解码原图缓存，不累计原图库，不持久化原图。
- 失败结果供已加入的调用者读取，但不会永久缓存；下一次可重试。
- 查询/权限失效会分离旧请求，新请求不加入旧任务，旧任务结束也不会填回新代缓存。

保留完整分辨率、原图无固定分配/边长/响应大小配额。网络超时、HTTP 状态和损坏图片错误检查仍保留。

## 原图阶段测量

执行 Release 的显式公开 SFW 测量：

```powershell
cargo test --release -p wh-desktop live_original_cold_and_reopen_timings -- --ignored --nocapture
```

`w5mqr6`，完整6240×4160 / 4,315,271字节：

- 总下载+解码+缓冲准备：约 **4232ms**。
- 网络（连接至读完响应）：约 **3913ms**。
- 解码与像素缓冲准备：约 **314ms**。
- 同加载器内缓存再次读取：约 **9μs**，共享原像素缓冲。

真实详情窗口另一次样本显示“网络2.39s / 解码0.35s / 6240×4160”。这说明该样本主要慢在传输，不能承诺所有图片/网络都如此；微秒缓存读取不等于整个窗口绘制耗时。没有同网络条件的稳定旧版基准，不宣称整体首次加载固定提速百分比。确定消除的是同图并发重复传输/解码。

## 已知范围与后续方向

- 本轮仅针对窗口位置、图片/作者多开和加载可观察性，不能给整个应用打满分；完整跨显示器DPI、屏幕阅读器、长时间大量窗口压力未验收。
- 多个完整原图窗口会占用真实内存；用户主动多开的各实例各自持有图片，缓存共享能避免同图重复像素，不把系统资源说成无限。
- 关闭窗口后丢弃该窗口结果，正在进行的共享 HTTP/解码可能继续到结束，不宣称已完成逐任务即时取消/下载队列。
- 原主窗口详情组件仍作为兼容/历史回归代码保留，但生产卡片入口已改到 WindowHub，不再触发原页面详情切换。
- 登录定位已编译和本地原生回归检查，未进行真实认证弹窗的中心坐标/安全验证验收；网站间歇验证问题仍是已知限制。
- 站内写入和真实桌面壁纸效果未在本轮执行，不能以按钮存在代替接受验收。
