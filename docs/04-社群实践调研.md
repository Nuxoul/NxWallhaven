# 社群实践调研：别人是怎么做 wallhaven 客户端的

> 调研时间：2026-10-19
> 方法：GitHub API 全量检索（`wallhaven` 关键词共 **1175** 个仓库），逐个核实技术栈、平台支持、活跃度

## 一、最重要的发现：**没有人做成过真正的 wallhaven 双端项目**

这是本次调研最关键的一条。

```
GitHub 搜索 "wallhaven android desktop"  →  total_count = 0
GitHub 搜索 "wallhaven compose multiplatform" →  total_count = 1（且不含桌面端）
```

**1175 个 wallhaven 相关仓库里，没有一个同时支持 Windows + Android 的成品项目。**

这不是巧合。说明「双端」是这个领域公认的空白，也说明**这活儿确实有难度**——大量项目止步于单端或纯下载脚本。

## 三、三个必须细看的项目

### 3.1 ★ Attacktive/Wallhavend-android —— Kotlin 路线的活证据

**这是最有参考价值的项目**：真实上架 Google Play（`xyz.attacktive.wallhavend`，100+ 下载），持续更新到 2026-10。

**它的依赖清单（实测抓取 `gradle/libs.versions.toml`）**：

```toml
agp = "9.4.1"              # 与我们调研的 AGP 稳定线完全一致
kotlin = "2.4.21"          # 与我们调研的 Kotlin 版本完全一致
composeBom = "2026.09.00"
lifecycle = "2.11.0"
retrofit = "3.0.0"
okhttp = "5.5.0"
coil = "2.7.0"
work = "2.12.0"            # WorkManager 做定时轮换
hilt = "2.60.1"
datastore = "1.2.1"
```

**它的 build.gradle.kts 关键配置**：
```kotlin
compileSdk = 37     // 与本机 SDK 37 一致
minSdk = 26         // ★ 与我们在方案中定的 minSdk 26 完全一致
targetSdk = 37
```

**它验证了什么**：
- ✅ `minSdk 26` 是社群的**共识选择**，不是我拍脑袋
- ✅ WorkManager + Retrofit + Coil + Hilt 是 Android 壁纸应用的标准组合
- ✅ 功能描述印证了我们的 API 理解：「按 category/purity/aspect ratio 过滤」「NSFW 仅需 API Key」「后台轮换受系统节流，间隔是近似值」
- ✅ 已实现**自动轮换壁纸**——证明 M4 的桌面增强功能在技术上是通的

**它没做什么**：只有 Android，没有桌面端。

### 3.2 ★ PyrovSergey/MyGalleryKMP —— 与我的推荐几乎完全一致

README 原文：

> MyGallery — **Kotlin Multiplatform** wallpaper app for Android & iOS. Browse categories, scroll through HD wallpapers with infinite pagination, and view images in full-screen with pinch-to-zoom. Built with **Compose Multiplatform, Ktor, Coil 3, and MVVM** architecture. Powered by **Wallhaven API**.

**这几乎就是我方案里写的技术组合**：Compose Multiplatform + Ktor + Coil 3 + MVVM + Wallhaven API。

但它有一个致命遗漏——**build.gradle.kts 里只有 `androidTarget()` 和 `iosArm64()/iosSimulatorArm64()`，没有 jvm/desktop 目标**：

```kotlin
kotlin {
    androidTarget { ... }
    listOf(iosArm64(), iosSimulatorArm64()).forEach { ... }
    // 没有 jvm("desktop")
}
```

**这恰恰暴露了本项目的价值**：他们做了 Android + iOS，我们做 Windows + Android——**方向不同，且都用同一套 CMP 代码**。我们要做的，是把这个已验证的技术组合补上桌面端。

### 3.3 ★ BooruFlow —— 唯一真·五端项目，但代价是 Flutter

**这是唯一一个真正做到 "Android + Windows + Linux + macOS + iOS" 的同类项目。** 它的架构值得学习：

```
BooruFlow/
├─ android/   ios/   windows/   linux/   macos/   ← 五个平台目录
├─ lib/                                          ← Flutter/Dart 代码
├─ rust/                                         ← Rust 核心
│   └─ src/
└─ flutter_rust_bridge.yaml                      ← 桥接配置
```

`flutter_rust_bridge.yaml` 实际内容：
```yaml
rust_input: crate::api
rust_root: rust/
dart_output: lib/src/rust
enable_lifetime: true
```

**它采用「Flutter 做 UI + Rust 做核心 + flutter_rust_bridge 桥接」的架构**，正好是我在方案 D 里提出的思路的 Flutter 版本。

**它证明了什么**：
- ✅ 多端 wallhaven 客户端**技术可行**，有人真做到了
- ✅ Rust 作为**共享核心库**、前端换任意 UI 框架，是**已被验证的成熟路线**

**它的代价**：
- ⚠️ 维护 Dart + Rust 两套语言
- ⚠️ 五端构建链非常重
- ⚠️ 只有 42 星，说明这种复杂架构的推广度不高

## 四、这份社群数据对我的选型推荐意味着什么

### 4.1 我的推荐被强化了，而不是被推翻

原推荐：**Kotlin + Compose Multiplatform 单代码库**

社群证据支持：

| 证据 | 含义 |
|---|---|
| `Wallhavend-android` 用 Kotlin+Compose 上架 Play，minSdk 26 | Kotlin 是 Android 壁纸应用的主流选择 |
| `MyGalleryKMP` 用 CMP+Ktor+Coil3+KMP 接 Wallhaven API | **技术组合已被真实项目验证** |
| Kotlin/Rust/Dart 各 5 个项目，势均力敌 | 没有哪种语言显著占优，选型应看**项目形态匹配度** |
| **零个**项目同时做 Windows+Android | 我们的目标是**空白地带**，需要自己做决策 |

### 4.2 但有一条我之前低估了：Rust 在壁纸领域的实际存在感

`liixini/skwd-wall` 有 **1081 星**，是 Rust 项目里最成功的，比大多数 Kotlin 项目热得多。它的定位是「aesthetics-first wallpaper selector and engine with **extreme performance**」，支持图片/视频/Wallpaper Engine 场景。

**但注意它的 topics：`linux`, `kde-plasma`, `hyprland`, `nixos`, `wayland`** —— 它**只服务 Linux 桌面**，是 Linux ricer 社区的产物，**完全没有移动端**。

这说明：**Rust 在壁纸软件领域赢的是「Linux 桌面的极致性能与系统集成」，不是「跨端」**。这与我们的判断一致——Rust 的强项和本项目的需求方向不同。

### 4.3 一个值得警惕的信号：最火的两个 Electron 项目都停更了

| 项目 | Star | 停更时间 |
|---|---|---|
| leoFitz1024/wallhaven | 1588 | 2024-06（2 年 4 个月） |
| MaLuns/wallhaven-electron | 92 | 2022-12（3 年 10 个月） |

**Electron 方案在这个领域大规模存在，但生命周期短。** 一个可能的原因是：Electron 的包体（100MB+）与内存占用让维护者疲惫，或者作者兴趣转移。

对我们的启示：**包体不是唯一问题，长期可维护性更重要。** 这条反而支持 Kotlin（一套代码）而非 Flutter+Rust（两套）或 Electron（前端+Node）。

## 五、修正与新增结论

### 5.1 修正：Flutter 是我之前低估的选项

我原文档把 Flutter 排在 Kotlin 之后且理由较弱。**现在必须修正**：

`BooruFlow` 证明了 **Flutter + Rust 是唯一已被验证的「五端 wallhaven 客户端」架构**。如果你想的是「一次做全平台」，Flutter 路线的**实战证据比 Kotlin 更充分**（因为没人在 Kotlin 上做到 Windows+Android）。

本机没装 Flutter，但这不是否决理由——装一下即可。

### 5.2 保持：仍然推荐 Kotlin + CMP，但理由更精确了

不是「因为 Kotlin 更好」，而是：

1. **你的目标恰好是 Kotlin 的最大优势区**：Android 原生（Kotlin 主场）+ Windows 桌面（CMP 已实测出窗口）
2. **你不需要 5 个平台**，只需 2 个 → Flutter 的跨端广度优势用不上
3. **`MyGalleryKMP` 已证明 CMP+Ktor+Coil3+Wallhaven API 这个组合可行**，我们只需补桌面端
4. **`Wallhavend-android` 已证明 minSdk 26 + WorkManager + Coil 是标准解法**，可直接借鉴

### 5.3 备选方案优先级更新

基于社群证据，若要改选，优先级如下：

| 方案 | 社群证据强度 | 适用条件 |
|---|---|---|
| **Kotlin + CMP** | ⭐⭐⭐⭐（两个真实项目分别验证了 Android 与 KMP 组合） | 目标仅 Windows+Android（推荐） |
| **Flutter + Rust** | ⭐⭐⭐⭐⭐（BooruFlow 五端验证） | 想一次覆盖更多平台 |
| **Rust + Tauri** | ⭐⭐⭐（ErKeLost 单桌面端验证） | 极在意体积 |
| **Rust + Slint** | ⭐（无 wallhaven 项目采用） | 嵌入式场景 |

## 六、可直接抄的社群经验（进 M0/M1 时用）

### 来自 Wallhavend-android
```kotlin
minSdk = 26
compileSdk = 37
targetSdk = 37
// 依赖：compose-bom 2026.09.00 / work 2.12.0 / coil 2.7.0 / retrofit 3.0.0
//      hilt 2.60.1 / datastore 1.2.1 / lifecycle 2.11.0
```
- 壁纸轮换用 **WorkManager**，并明确告知用户「系统空闲时会延后，间隔是近似值」
- NSFW 用**运行时输入 API Key**，不硬编码，不用 release keystore 打包

### 来自 MyGalleryKMP
```kotlin
compileSdk = libs.versions.android.compileSdk
// commonMain: compose.runtime/foundation/material3/ui
//              ktor.client.core + content.negotiation + serialization.kotlinx.json
//              coil.compose + coil.network.ktor
//              koin（依赖注入）+ navigation.compose
//              zoomable（图片缩放）
```
- 用 **Koin** 而不是 Hilt 做跨平台 DI（Hilt 只支持 Android，KMP 项目用不了）
- 图片缩放用 `zoomable` 库
- 无限分页用 `navigation-compose` + ViewModel

### 来自 BooruFlow
- 若将来要加第三端（iOS/macOS），再引入 `flutter_rust_bridge` 把核心逻辑抽到 Rust
- **不要一开始就这么做**——它是五端项目，你只有两端

## 七、结论

1. **没有人做成过 wallhaven 的 Windows+Android 双端** → 这是个真实空白，值得做
2. **Kotlin + CMP 的核心技术假设已被两个真实项目分别验证**（Android 端 + KMP 组合）
3. **Flutter + Rust 是唯一五端验证方案**，但对你只需要两端的情况属于过度设计
4. **Rust 在壁纸领域最强的是 Linux 桌面极致性能**（skwd-wall 1081★），与本项目需求方向不重合
5. **Electron 最火但都停更了** → 包体和维护成本是真实杀手

**推荐不变：Kotlin + Compose Multiplatform。**
但如果你希望「一次覆盖 Windows/Android/iOS/macOS/Linux 全部」，我改推 **Flutter + Rust**（有 BooruFlow 背书）。
