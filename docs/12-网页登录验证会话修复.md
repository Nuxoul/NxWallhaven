# WebView2 同会话登录修复

## 用户报告与根因

`网站登录未完成：human verification is required in a browser`。

此前纯 HTTP 登录遇到网站安全验证即返回错误；“外部浏览器登录/验证”入口与 reqwest Cookie jar 分离，验证后的会话没有回流，不是可用的验证衔接。

## 本轮修改

- 删除设置中的网站用户名/密码输入框。运行路径不再通过 reqwest 提交网站密码。
- 使用应用自己的 WebView2 二级窗口显示 Wallhaven 原始登录页，由本人完成验证/登录。
- 当前页面账号确认、收藏夹 HTML GET、收藏 POST 全部在同一 WebView/浏览器配置内执行，不导出 Cookie 给 HTTP 客户端。
- 账号确认只读取用户面板、移除 input/textarea/script，附带验证标记；不读取登录表单或密码值，不向日志输出正文、Cookie、CSRF。
- 请求仅允许 Wallhaven 同源，限制响应大小；POST `redirect: error` 且不自动重试，提交后再读状态核对。
- WebView2 使用独立临时浏览器配置，不读取系统浏览器数据；运行时可能把会话写入该临时配置，退出时尽力清理，不保证异常退出时完全不落盘。
- 关闭/超时保留待登录浏览器，重新打开继续同一会话；明确退出才取消等待并丢弃。
- 使用中文提示区分等待、关闭、创建失败、需本人验证、过期及写入结果未确认。

## 真实桌面测试发现并修复的原生崩溃

首次真实 Slint 应用内创建 Tao/WebView2 时出现内存访问异常，虽然单独 WebView2 测试通过。核对依赖源码发现：Tao 与 Slint/winit 默认都注册 `Window Class`，但回调和数据结构不同。

为网页登录窗口设置唯一类名 `WallHavenStudio.WebLogin.WebView2` 后，真实应用复测成功：主窗口、设置窗口、网站登录窗口同时存在，进程 Responding=True。新增防止回退到默认类名的断言。

5. 同传输 fixture 覆盖登录、收藏/取消、重复期望状态不重复 POST、取消/超时后保留实例、过期结果拒绝和同源限制。
